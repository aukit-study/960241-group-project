## 📌 1. สรุปภาพรวมโจทย์และสิ่งที่ต้องทำ

โปรเจคนี้เป็นการจำลองสถานการณ์ที่ **กลุ่มเพื่อนสนิท 4 คน รวมตัวกันเปิดบริษัทพัฒนาซอฟต์แวร์ (Software House / Tech Agency)** โดยต้องจัดทำเว็บไซต์เพื่อโปรโมทบริษัทและแสดงผลงานของทีม
* **เทคโนโลยี:** เว็บไซต์ Static (HTML / CSS / JavaScript) **ไม่ต้องต่อ Database และไม่ต้องทำ Server Backend**
* **สิ่งสำคัญ:** เน้นการออกแบบที่สวยงาม ทันสมัย Responsive รองรับมือถือ/คอมพิวเตอร์ และการเชื่อมต่อลิงก์ระหว่างหน้าต่างๆ อย่างสมบูรณ์

### 📑 โครงสร้างหน้าเว็บที่ต้องมี (Sitemap)
1. **หน้าหลักบริษัท (Home / Landing Page):**
   - แนะนำชื่อบริษัท, สโลแกน, วิสัยทัศน์ และจุดเด่น
   - บริการที่เชี่ยวชาญ (เช่น พัฒนาระบบ POS, E-Commerce, Mobile App, Web Application, Cloud Solution)
   - ตัวอย่างผลงานที่ผ่านมา (Case Studies / Portfolio Showcase) เช่น จำลองว่าเคยพัฒนาระบบ POS ให้กับ 7-11 หรือระบบบริหารจัดการต่างๆ *(ส่วนนี้คือคะแนนกลุ่มหลัก)*
2. **หน้าทีมและโปรไฟล์รวม (Team Profile / About Us):**
   - แนะนำสมาชิกในทีม บทบาทหน้าที่ (PM/PO, SA, Dev, Designer)
   - มีรูปภาพและข้อมูลเบื้องต้น พร้อม **ปุ่มลิงก์แยกไปยัง Portfolio ของแต่ละคน**
3. **หน้าพอร์ตโฟลิโอเดี่ยวของแต่ละคน (Individual Portfolio x 4 หน้า):**
   - รูปโปรไฟล์, ประวัติส่วนตัว, ประสบการณ์ตั้งแต่โรงเรียนจนถึงปัจจุบัน
   - ทักษะความสามารถ (Skills / Tech Stack), ผลงานที่ผ่านมา, ช่องทางติดต่อ
   - ตกแต่งอิสระ เน้นลูกเล่น (Animations / Interactive) และความสวยงาม *(ส่วนนี้คือคะแนนเดี่ยวหลัก)*

## 🗂️ 3. โครงสร้างโฟลเดอร์ที่แนะนำ (Folder Structure)

## 🔄 4. ขั้นตอนการทำงานร่วมกันทีละสเต็ป (Workflow & Integration Guide)

### 🔹 สเต็ปที่ 1: เตรียมระบบและวางโครงสร้าง (หัวหน้ากลุ่ม + Designer)
1. **หัวหน้ากลุ่ม:** สร้าง Online Repository บน GitHub และเพิ่มสมาชิกทั้ง 3 คนเป็น Collaborators
2. **สร้าง `.gitignore`:** ใส่ไฟล์ที่ไม่อยากให้ขึ้น Git เช่น `.DS_Store`, `Thumbs.db`, `.vscode/`
3. **Designer:** กำหนด Color Palette, Google Fonts, และสร้าง Navbar / Footer Template กลางไว้ให้เพื่อนๆ นำไปใช้

### 🔹 สเต็ปที่ 2: ดึงงานไปทำแยกส่วน (สมาชิกทุกคน)
1. สมาชิกทุกคน `git clone` หรือ `git pull` โปรเจคหลักลงมาที่เครื่องตนเอง
2. **แนะนำให้แยก Branch ในการพัฒนา:**
   - `git checkout -b feature/member1-portfolio`
   - `git checkout -b feature/member2-portfolio`
   - `git checkout -b feature/member3-portfolio`
   - `git checkout -b feature/member4-portfolio`
3. สมาชิกแต่ละคนเข้าไปพัฒนาไฟล์ในโฟลเดอร์ `portfolios/memberX-.../` ของตัวเอง **ห้ามแก้ไขไฟล์นอกโฟลเดอร์ของตัวเองในระหว่างนี้** เพื่อป้องกันการเกิด Conflict

### 🔹 สเต็ปที่ 3: รวมงานเข้าสู่โปรเจคหลัก (Merge & Integration)
1. เมื่อแต่ละคนทำ Portfolio เสร็จ ให้ Push Branch ขึ้น GitHub แล้วสร้าง Pull Request (PR) หรือส่งโค้ดให้หัวหน้ากลุ่ม
2. **หัวหน้ากลุ่ม:** ทำการ Merge โค้ดของทุกคนเข้ามาที่ Branch `main`
3. เชื่อมต่อลิงก์ในหน้า `team.html` ไปยัง `portfolios/memberX/index.html` ของแต่ละคน
4. ในหน้า Portfolio ของแต่ละคน ต้องมีปุ่ม **"← กลับสู่หน้าหลักบริษัท (Back to Company)"** ลิงก์กลับมาที่ `../../index.html` หรือ `../../team.html`

### 🔹 สเต็ปที่ 4: ตกแต่ง ปรับจูน และ QA (ทุกคนร่วมกัน)
1. ตรวจเช็คลิงก์ทุกจุดว่าคลิกแล้วเปิดได้ถูกต้อง ไม่เกิด 404 Not Found
2. ตรวจสอบการแสดงผลบนหน้าจอขนาดต่างๆ (Responsive Design)
3. ปรับแต่ง Animation, Transitions, Hover Effects ให้ดูพรีเมียมและลื่นไหล

## 🎤 6. แนวทางการเตรียมตัวนำเสนอ (Presentation Strategy)

1. **เปิดด้วยการแนะนำบริษัท (2-3 นาที):** หัวหน้ากลุ่ม/PM แนะนำชื่อบริษัท วิสัยทัศน์ และบริการเด่น
2. **โชว์ผลงานและระบบของบริษัท (3-4 นาที):** SA/Tech Lead พาดูเคสผลงานที่บริษัทเคยทำ (เช่น ระบบ POS 7-11 มีฟีเจอร์อะไรบ้าง แก้ปัญหาอะไรให้ลูกค้า)
3. **แนะนำทีมและให้แต่ละคนโชว์ Portfolio ตัวเอง (คนละ 1-2 นาที):** ทุกคนผลัดกันนำเสนอหน้า Portfolio ของตัวเอง แสดงลูกเล่น ความสวยงาม และประสบการณ์ที่ใส่ลงไป
4. **สรุปภาพรวมและการทำงานเป็นทีม (1 นาที):** อธิบายการแบ่งงาน บทบาท และการใช้ Git ในการรวมงาน
